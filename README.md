# Игра 5 Букв
## Идея
Консольная игра в духе Wordle. Программа загадывает слово из 5 русских букв, у игрока 6 попыток. После каждой попытки — подсказка по буквам:

Загадано: озеро
Ввод:     арбуз
Результат: ❌🟡❌❌🟡

✅ буква на месте   🟡 есть, но не там   ❌ буквы нет

## Зачем это в реальной работе
Геймификация — стандартный инструмент в финтехе, образовательных продуктах и маркетплейсах: ежедневные задания, стрики, бейджи, викторины, промо-игры с розыгрышем бонусов. Такие механики повышают вовлечённость и возвращают пользователей в приложение — и за каждой из них стоит тот же набор инженерных задач, что и в этом проекте.

«5 букв» — хороший пример такой механики: словарь, случайность, игровая сессия с ограничением попыток, валидация ввода, правила победы и поражения. И одна по-настоящему нетривиальная задача — корректная обработка повторяющихся букв, где наивное решение даёт неверный результат. Именно на таких «маленьких» правилах чаще всего и ловятся баги в продакшене.

## С чем придется столкнуться
Доменная модель и инварианты — игровая сессия, которая не может оказаться в невалидном состоянии
Разделение логики и I/O — ядро игры не знает про консоль
Валидация на границе системы — некорректный ввод не ломает состояние
Детерминированность — воспроизводимость поведения через seed
Тестирование поведения — включая кейс с повторяющимися буквами
Процесс Merge Request'ов — декомпозиция изменений к полноценным блокам, README

## План: три MR
### MR1 — Данные и сессия
Словарь (минимум 50 слов по 5 букв), случайный выбор слова с фиксируемым seed, модель сессии:

GameSession: answer, maxAttempts, attemptsUsed, attemptsHistory, status
status: IN_PROGRESS | WIN | LOSE
startGame(dictionary, maxAttempts, seed) -> GameSession
Инварианты: слово из словаря и ровно 5 букв, maxAttempts > 0, завершённая игра не принимает новые попытки.

### MR2 — Правила игры
applyGuess(session, guess) -> GuessResult
ввод без учёта регистра, только буквы, ровно 5, слово есть в словаре;
некорректный ввод не тратит попытку;
статусы ✅ 🟡 ❌, определение победы и поражения;
логика проверки отделена от консольного ввода-вывода.
Главная ловушка — повторяющиеся буквы. Каждая буква ответа «расходуется» один раз: сначала отмечаем все ✅, потом оставшимися буквами закрываем 🟡.

Загадано: сорок
Ввод:     оооом
Верно:    🟡❌❌✅❌     (а не 🟡🟡🟡✅❌ — свободных «о» столько нет)

### MR3 — Интерфейс и проверяемость
меню (новая игра / выход), несколько игр подряд без перезапуска, устойчивость к некорректному вводу;
фиксированный формат вывода:
❌🟡❌❌🟡 арбуз
Осталось попыток: 5
Победа! Слово угадано за 4 попытки
Неудача. Загаданное слово: озеро
детерминированный режим для автопроверки — любой из вариантов: запуск с seed, явно заданный ответ или команда вида check --answer озеро --guess арбуз.
Что должны покрывать тесты
Словарь	≥50 слов, ровно 5 букв, пустой словарь — ошибка
Seed	одинаковый seed → одинаковое слово
Валидация	длина, не-буквы, слово вне словаря; попытка не тратится
Проверка букв	базовый кейс + обязательно сорок / оооом
Финалы	WIN при угадывании, LOSE после 6 попыток + показ ответа
Меню	некорректный пункт не роняет программу; несколько игр подряд
